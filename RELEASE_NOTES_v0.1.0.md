# Restore Evidence v0.1.0

First release. `restore-evidence` documents the results of a backup restore
test you have already carried out, and checks the restored files against a
manifest you supply. It writes deterministic JSON and HTML reports.

## Features

- `validate` checks a manifest (`schema_version` 1) and prints its SHA-256
  digest.
- `verify` checks presence, size and SHA-256 for each listed file, plus
  optional directory-wide file count, total size and unlisted-file checks.
- Every check is reported as `verified`, `failed` or `not_performed`, with a
  reason when it was not performed. Results observed by the operator are
  recorded separately as supplied results and are never shown as verified.
- Outcome `pass`, `fail` or `incomplete`, with exit codes 0, 1 and 3; exit code
  2 for usage and input errors.
- JSON report (`report_schema_version` 1) for tooling, and a self-contained
  HTML report with no script and a restrictive Content-Security-Policy.
- Path redaction with `-redact-paths`, or per entry with `"sensitive": true`.

## Safety

- Never starts backups or restores, never runs commands, never opens network
  connections.
- Reads the restored directory through `os.Root`, does not follow symbolic
  links, and never writes to it.
- Rejects manifest paths that are absolute or contain `..`, and other unsafe
  forms.
- Never overwrites an existing file without `-force`, and never replaces a
  directory, symbolic link or the manifest even with it. Refuses to write
  reports inside the restored directory.
- Reports contain no file contents and no host paths.

## Limitations

A report records specific checks made at one time. It does not show that a
backup is recoverable in general, it is not a compliance certification, and it
is not tamper-evident. See
[docs/evidence-limitations.md](docs/evidence-limitations.md).

- Manifests are not generated by the tool.
- Only regular files are checked. Permissions, ownership, timestamps and
  extended attributes are not compared.
- Paths are compared case-sensitively on every platform.
- Hashing is sequential.

## Install

Download the archive for your platform from this release and check it against
`checksums.txt`, or:

```sh
go install github.com/JSP-IT/restore-evidence/cmd/restore-evidence@v0.1.0
```

Binaries are built with Go from `go.mod`, `CGO_ENABLED=0` and `-trimpath`, for
Linux, macOS and Windows on amd64 and arm64. Each archive contains the binary,
`LICENSE` (Apache-2.0), `NOTICE`, `LICENSE-go` (the Go standard library's
BSD-3-Clause license) and `README.md`.
